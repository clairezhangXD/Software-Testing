Discuss each attribute -- did your definition change when you shifted to a developer's perspective instead of a users? Why/why not? If if did, in what way?

reliability --> no, still about whether the software does the job the user requires

reusability --> not really, I think this attribute is only really applicable to the developer's perspective anyway (the capacity to reuse code)

testability --> not really, testability is about whether the code can be tested against the user's requirements/user stories in both perspectives

maintainability --> yes, maintainability could mean how well the user can manage the data that they store in the software, whereas maintainability from the developer's end is more about whether the code is well managed (packages, documentation, design, code smells) 

security --> no, security is defined the same for both

flexibility --> yes, flexibility to the user could be about how accessible features are to them or how much control they have over the settings, whereas it is more about how extensible the design of the software is from the developer's perspective

availability --> no, all about software up time

portability --> yes, portability refers to what devices the software is compatible with to users, whereas developers may not only consider device compatibility but also language portability to enable cross platform compatibility.

scalability --> yes, users think about scalability in terms of how much more they can get out of a feature (maybe they want to have additional storage), whereas scalability to developers is about accommodating these additions to the system (the feasibility of adding this additional storage)

interoperability --> yes, similar to portability

usability --> no, all about how easy it is for the user to operate the software

performance --> no, all about speed
