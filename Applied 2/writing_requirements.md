The following requirements are for a grocery story checkout system. For each of requirement, specify whether it is well written or poorly written. Justify your answer. You are welcome to discuss this with fellow students.

R1: The system shall display an accurate total cost from the start to the end of each transaction, rounded to the nearest cent.
well written --> Specific (nearest cent) and relevant (to the checkout system)

R2: Fast.
Poorly written --> fast can mean different things in terms of the system (fast interface? fast scanning?) 

R3: The system shall never crash.
Poorly written --> needs to be more specific (what aspect of the system shouldn't crash?)

R4: Users will enjoy using the system.
poorly written --> what does the system need to do allow the user to "enjoy" it? Not specific enough.

R5: The system shall print out a receipt and notify the user if the receipt paper is finished.
well written --> sets out specific instruction for the system to execute (print out a receipt) and the systems subsequent action to update the user, though it would be more ideal to highlight how the user should be "notified"

R6: System response time shall be 3 seconds.
poorly written --> Although this is a quantified requirement (3 seconds), it does not specify what aspect of the system should respond within this time.

Based on your answers, suggest three tips for writing good user requirements.
1. Be specific about what part of the system should have this requirement
2. Give a quantified benchmark for the system to meet.
3. Express when this requirement should be met (throughout the entire transaction or at a specific moment during it?)
