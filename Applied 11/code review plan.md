1. Building a Code Review
Instructions for Reviewees:
Before the Review
Reach out to someone on the team familiar with the section of code that you have changed. 
Give them an overview prior to the review including the branch name, the commit details and a summary of your changes so they are able to prepare accordingly. Explain why you made changes, and provide context on how this integrates with previous work - ask them to prepare any questions they might have to ensure understanding. 
Provide any relevant documentation to aid clarity, including the code files involved in the changes and of any ideas which originated offline.
Review your own changes and ensure that the code section is complete before requesting a review.
Check that the changes can be consolidated into one or several ideas so this can be relayed to your reviewer.

During the Review
Work together with the reviewer to go over the changes in detail. Discuss other approaches which were thought of as alternate(not chosen) strategies.
Ensure you cover the following aspects: 
Do the changes make sense to both parties and meet the requirements?
Do the changes result in breaking any other code, or require new tests to be constructed?
Do the changes adhere to the coding standards (ie. docstring format, linting etc.) decided by the team for the project?
Do the changes enhance the code or make it more readable? Or are they decreasing the code quality?


After the Review
Remember to thank your reviewer for their assistance and time.
Provide constructive feedback

Instructions for Reviewers

Before the Review
Go over the relevant files and documentation provided
Come up with any questions to clarify and misunderstandings 

During the Review
Actively listen to changes that have been proposed.
Attempt to understand the background of why changes have been made.
As in the “During the Review - Reviewee” section
Use linters and formatters to help identify improvements that can be made

After the review
Tell the reviewer if you learnt anything new during the code review
Provide constructive feedback on the code and their review process

Code Review Review:
Concise
Easy to follow
No jargon 
Requirements are met
During the review, if you feel you do not understand the code base well enough to conduct a review (to be a reviewer), perhaps recommend another team member to take your place. 
Add tools that the reviewer can use (linters, formatters)
